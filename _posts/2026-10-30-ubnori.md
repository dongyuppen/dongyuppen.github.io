## 💡 프로젝트 개요
**윱놀이**는 University의 '윱'과 윷놀이의 '놀이'를 합친 이름으로, **학적 인증을 거친 대학 구성원만 참여하는 대학교 대항전 온라인 윷놀이**입니다. 플레이어는 자기 학교의 마스코트를 말로 삼아 다른 학교 학생과 실시간 1:1로 맞붙고, 한 판 한 판의 결과가 학교 점수로 누적되어 주간·시즌 랭킹을 다툽니다.

윷놀이 규칙을 대학 생활 맥락으로 다시 썼습니다. 말이 하나씩 날 때마다 2학년 → 3학년 → 4학년으로 진급하고, **네 말이 모두 나면 '졸업 = 승리'** 가 되는 식입니다.

기획·백엔드·프론트엔드·인프라를 **혼자 설계하고 개발하는 개인 프로젝트**이며, 2026년 10월 말 착수해 현재 개발을 진행하고 있습니다.

## 🛠 사용 기술
- **Backend:** Java 21, Spring Boot 4, Spring Data JPA, **STOMP over WebSocket**
- **Database:** MySQL 8.4, Redis 7
- **Frontend:** React, TypeScript, Vite, **PixiJS**(게임 보드 렌더링)
- **Infrastructure:** AWS(ECS Fargate, RDS, ElastiCache, S3, CloudFront), **Terraform**(IaC)
- **개발 환경:** Docker Compose(MySQL·Redis·S3Mock), Testcontainers, Spotless, GitHub Actions(CI)

## 📌 핵심 설계 포인트

### 1) 실시간 1:1 대전 — STOMP over WebSocket *(설계 확정, 구현 예정)*
- 턴제 대전 특성상 서버가 양쪽 플레이어에게 상태 변화를 **동시에 밀어줘야** 하므로, 폴링 대신 STOMP over WebSocket을 선택했습니다.
- 게임 세션 상태와 매칭 대기열은 Redis에 두어, 애플리케이션 인스턴스가 늘어나도 **특정 서버에 세션이 묶이지 않도록** 설계했습니다.
- `game` · `match` · `ranking` 패키지로 경계를 먼저 잡아두고, 인증·학적 검증이 끝난 뒤 채워 넣는 순서로 진행하고 있습니다.

### 2) 학적 인증 — 신뢰 가능한 "우리 학교 사람"
프로젝트에서 가장 먼저, 가장 공들여 만든 부분입니다. 학교 대항전이라는 콘셉트는 **소속의 진위가 전제되지 않으면 성립하지 않기** 때문입니다.

- **상태 기계로 설계:** 신청 → 심사 대기 → 승인/반려 → (반려 시) 재제출의 전이를 `VerificationStatus`·`RejectReason`으로 명시하고, 계정 쪽 `AccountStatus`와 연동해 **승인 전 계정은 게임 기능에 접근할 수 없도록** 역할·상태 기반 접근 제어를 걸었습니다.
- **업로드는 서버를 거치지 않게:** 증명서를 **S3 Presigned PUT URL**로 클라이언트가 직접 올리도록 해 서버가 파일 트래픽을 떠안지 않게 했습니다. 대신 `UploadPolicy`·`VerificationFileInspector`로 확장자·크기 등 허용 범위를 서버가 정의·검증합니다.
- **개인정보를 다루는 화면이라는 전제:** 증명서에는 이름·학번 등 민감정보가 담기므로, 관리자가 파일을 보려면 **별도의 열람 링크를 발급**받아야 하고 그 **열람 기록이 남도록** 설계했습니다. 심사 행위 자체도 `AdminAuditLog`로 감사 로그를 남깁니다.
- 로컬 개발에서는 S3를 **S3Mock 컨테이너로 대체**해 AWS 자격증명 없이도 업로드 경로 전체를 테스트할 수 있게 했습니다.

### 3) 처음부터 배포를 전제한 환경 구성
- 로컬 MySQL을 **3307 포트**로 띄워 개발자 PC에 이미 설치된 MySQL(3306)과 충돌하지 않도록 했고, 접속 정보는 `.env`로 분리해 커밋되지 않게 했습니다.
- `local` / `dev` / `prod` 세 프로파일로 나누고 운영은 **Redis TLS**를 사용하도록 구분했습니다.
- 테스트는 **Testcontainers 기반 MySQL**로 실제 DB에 맞춰 검증하고, `spotless`로 포맷을 강제해 CI에서 함께 검사합니다.
- 인프라는 콘솔 수작업이 아니라 **Terraform 코드로 관리**해, 재현 가능한 상태로 유지하고 있습니다.

## 📈 이 프로젝트에서 의도한 것
- 크루윙에서 **이미 돌아가는 서비스를 운영·개선**하는 경험을 쌓았다면, 윱놀이는 **빈 저장소에서 아키텍처를 직접 결정**하는 경험을 의도한 프로젝트입니다.
- 실시간 양방향 통신(WebSocket), IaC(Terraform), 컨테이너 오케스트레이션(ECS Fargate) 등 **기존 프로젝트에서 다루지 않았던 영역**을 의식적으로 선택했습니다.
- 로컬 환경 구성(포트 충돌 회피, S3Mock, Testcontainers)부터 문서화해, **다른 사람이 clone 해서 바로 띄울 수 있는 저장소**를 기준으로 삼았습니다.
